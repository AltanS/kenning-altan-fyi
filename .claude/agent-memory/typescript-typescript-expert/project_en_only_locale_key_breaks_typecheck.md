An English-only key addition to `app/locales/en/common.json` breaks two gates, not one.

- `app/emails/i18n.server.ts` declares `satisfies Record<LanguageCode, { common: typeof enCommon }>`, so `de/common.json` is TYPE-CHECKED against the English catalogue. A missing German key is `error TS2719` there, and nowhere near the file you edited.
- `tests/unit/i18n-locales.test.ts` asserts the same key SET in every locale and namespace.

**Why:** the German copy is generated by the workspace `wordsmith` CLI in a separate pass, so a task that says "do not write German" leaves both gates red by construction.

**How to apply:** when copy lands before its translation, say so in the report and name the two failures. To prove your own code is clean, fill `de/common.json` from the English values in a scratch edit, run `pnpm typecheck` and the unit tier, then restore the file and confirm the md5 matches.
